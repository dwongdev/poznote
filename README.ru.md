## Установка

> Официальный образ мультиархитектурный (linux/amd64, linux/arm64): он работает в Windows/macOS через Docker Desktop, а также на устройствах ARM64, таких как Raspberry Pi, NAS и т. д.

Выберите удобный для вас способ установки:

<a id="windows"></a>
<details>
<summary><strong>🖥️ Windows</strong></summary>

#### Шаг 1: предварительные требования

Установите и запустите [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)

#### Шаг 2: развертывание Poznote

Создайте новый каталог:

```powershell
mkdir poznote
```

Перейдите в каталог Poznote:
```powershell
cd poznote
```

Создайте файл окружения:

```powershell
curl -o .env https://raw.githubusercontent.com/timothepoznanski/poznote/main/.env.template
```

Отредактируйте файл `.env`:

```powershell
notepad .env
```

Скачайте файл конфигурации Docker Compose:

```powershell
curl -o docker-compose.yml https://raw.githubusercontent.com/timothepoznanski/poznote/main/docker-compose.yml
```

Скачайте последние версии образов Poznote Webserver и Poznote MCP:
```powershell
docker compose pull
```

Запустите контейнеры Poznote:
```powershell
docker compose up -d
```

</details>

<a id="proxmox"></a>
<details>
<summary><strong>🗄️ Proxmox VE</strong></summary><br>

На хосте Proxmox VE проект Proxmox VE Community Scripts устанавливает Poznote в отдельный контейнер одной командой, без Docker: он создает непривилегированный LXC-контейнер на Debian 13 (по умолчанию 1 vCPU, 512 МБ оперативной памяти и диск на 4 ГБ) и запускает Poznote внутри него на nginx и PHP.

Выполните эту команду в оболочке хоста Proxmox:

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/community-scripts/ProxmoxVE/main/ct/poznote.sh)"
```

После этого Poznote доступен по адресу `http://<container-ip>:8040` с теми же учетными данными по умолчанию, что и при любой другой установке. Чтобы обновить его позже, выполните `update` в консоли контейнера.

Этот скрипт написан и поддерживается сообществом, а не Poznote. Его параметры и примечания описаны на [странице скрипта Poznote](https://community-scripts.org/scripts/poznote).

<a id="rootless"></a>
<details>
<summary><strong>🔒 Rootless</strong></summary><br>

Poznote также поставляется в варианте образа rootless, который полностью работает от имени непривилегированного пользователя (uid/gid `1000`), а не от root. Он предназначен для сред, где root внутри контейнеров запрещен (ограниченный `PodSecurityStandard` в Kubernetes, rootless Podman, `docker run --user` и т. д.). Он работает точно так же, как образ по умолчанию; отличий всего два: внутри контейнера он слушает порт `8080` и не может исправить владельца вашего каталога данных при запуске.

#### Шаг 1: предварительные требования

1. Установите [Docker engine](https://docs.docker.com/engine/install/)
2. Установите [Docker Compose](https://docs.docker.com/compose/install/linux)

#### Шаг 2: развертывание Poznote

Создайте новый каталог:
```bash
mkdir poznote
```

Перейдите в каталог Poznote:
```bash
cd poznote
```

Создайте каталог данных и назначьте его владельцем uid/gid `1000` (**обязательно**: в отличие от образа по умолчанию, rootless-контейнер не может сам исправить владельца при запуске):
```bash
mkdir -p data
sudo chown -R 1000:1000 data
```

`sudo` здесь часто не нужен: если у вашего пользователя уже uid `1000`, `chown` можно пропустить, а в rootless Podman/Docker эту команду можно выполнить без root, см. [Запуск в режиме rootless](docs/TROUBLESHOOTING.ru.md#running-rootless).

Создайте файл окружения:
```bash
curl -o .env https://raw.githubusercontent.com/timothepoznanski/poznote/main/.env.template
```

Отредактируйте файл `.env`:
```bash
vi .env
```

Скачайте файл конфигурации Docker Compose для rootless:
```bash
curl -o docker-compose.rootless.yml https://raw.githubusercontent.com/timothepoznanski/poznote/main/docker-compose.rootless.yml
```

Скачайте последние версии rootless-образа Poznote Webserver и образа Poznote MCP:
```bash
docker compose -f docker-compose.rootless.yml pull
```

Запустите контейнеры Poznote:
```bash
docker compose -f docker-compose.rootless.yml up -d
```

Чтобы перевести существующий экземпляр Poznote на вариант rootless, а также за подробностями обращайтесь к разделу [Запуск в режиме rootless](docs/TROUBLESHOOTING.ru.md#running-rootless) руководства по устранению неполадок.

</details>

## Изменение настроек

Большинство повседневных настроек меняется в интерфейсе Poznote. Файл `.env` используйте только для параметров развертывания и среды выполнения, которые считываются при запуске контейнеров.

Файл `.env` используется для:

- `HTTP_WEB_PORT`
- `POZNOTE_OIDC_CLIENT_ID`
- `POZNOTE_OIDC_CLIENT_SECRET`
- `POZNOTE_OIDC_DISABLE_NORMAL_LOGIN`
- Необязательных переопределений среды выполнения, например `POZNOTE_MCP_PORT` и `POZNOTE_DEBUG`
- `POZNOTE_PHP_FPM_MAX_CHILDREN`, чтобы изменить число одновременных запросов PHP (по умолчанию 10) на нагруженном экземпляре, см. [руководство по устранению неполадок](docs/TROUBLESHOOTING.ru.md#the-app-stops-answering-under-load)
- `POZNOTE_PHP_MEMORY_LIMIT`, чтобы изменить лимит памяти PHP на один запрос, в МБ (по умолчанию 512), см. [руководство по устранению неполадок](docs/TROUBLESHOOTING.ru.md#a-request-runs-out-of-memory)
- `POZNOTE_SETTINGS_PASSWORD`, чтобы запрашивать дополнительный пароль перед открытием страницы настроек (по умолчанию пусто)
- `POZNOTE_MCP_AUTH_TOKEN`, чтобы требовать bearer-токен от MCP-клиентов, см. [MCP-сервер](#mcp-сервер)

Интерфейс используется для:

- Административных и глобальных настроек, таких как параметры провайдера OIDC, включение Git Sync, лимиты импорта и загрузка пользовательского CSS
- Настроек пользователя и профиля, таких как пароли локальных учетных записей, тема, размеры шрифта, сортировка заметок, фон рабочего пространства и скрытые элементы интерфейса

## Аутентификация

Poznote поддерживает несколько способов аутентификации, включая локальные учетные записи и внешних провайдеров удостоверений. Приложения и расширения, работающие с REST API, используют **пароли приложений**: это отдельные учетные данные, описанные ниже.

<details>
<summary><strong>Аутентификация через локальные учетные записи</strong></summary>
<br>

Poznote проверяет пользователей по их профилю, используя имя пользователя или адрес электронной почты и пароль.


#### Учетная запись по умолчанию

При новой установке Poznote создает один активный профиль администратора:

- Имя пользователя: `admin_change_me`
- Пароль: `admin`

После первого входа смените пароль по умолчанию и переименуйте учетную запись.

#### Управление паролями

Пароли управляются через веб-интерфейс Poznote, а не через `.env`:

- Пользователи могут сменить свой пароль в **Настройки > Сменить пароль**.
- Администраторы могут задать собственный пароль любому пользователю или сбросить его до значения по умолчанию в **Настройки > Инструменты администратора > Управление пользователями**.
- Опция **Запомнить меня** сохраняет сессию на 30 дней.
- Смена пароля аннулирует существующие cookie «запомнить меня» этого пользователя.

#### Пароли по умолчанию

- Учетные записи администраторов: `admin`
- Учетные записи обычных пользователей: `user`

Пока пользователь не сменил пароль, используется указанное выше значение по умолчанию. Как только пароль изменен через интерфейс, в базе данных сохраняется надежный хеш bcrypt, и он имеет приоритет.

</details>

<a id="oidc"></a>
<details>
<summary><strong>Аутентификация OIDC / SSO (необязательно)</strong></summary>
<br>

Poznote поддерживает OpenID Connect (authorization code + PKCE) для интеграции единого входа. Это позволяет пользователям входить через внешних провайдеров удостоверений, таких как Auth0, Keycloak, Azure AD или Google Identity.

#### Как это работает

1. Когда OIDC включен, на странице входа отображается кнопка `Continue with [Provider Name]`.
2. Пользователи проходят аутентификацию по потоку authorization code OIDC, защищенному PKCE.
3. Доступ можно ограничить разрешенными группами и, при необходимости, устаревшим списком разрешенных пользователей.
4. После аутентификации Poznote связывает удостоверение с профилем в следующем порядке: `sub` (`oidc_subject`), затем `preferred_username`, затем `email`.
5. Если автоматическое создание пользователей включено и ни один профиль не подходит, Poznote создает его автоматически. У такого профиля **нет пароля вообще**: он не проходил через передачу начальных учетных данных, которую выполняет администратор при создании учетной записи, поэтому пароль по умолчанию к нему не подходит. Вход выполняется через провайдера, либо администратор задает явный пароль в **Настройки > Инструменты администратора > Управление пользователями**.
6. Если `POZNOTE_OIDC_DISABLE_NORMAL_LOGIN=true`, форма с именем пользователя и паролем скрывается, и на странице входа остается только SSO.
7. Когда OIDC включен, клиенты REST API могут проходить аутентификацию с помощью `Authorization: Bearer <OIDC JWT>`; Poznote проверяет JWKS провайдера, издателя, срок действия, аудиторию и настроенные ограничения доступа.
8. Клиенты, которые вообще не могут пройти поток OIDC (расширение браузера, мобильное приложение, скрипты), используют вместо этого [пароль приложения](#app-passwords), который каждый пользователь создает в своих настройках.

#### Настройка

OIDC настраивается в **интерфейсе администратора**: откройте **Настройки > Инструменты администратора > OIDC / SSO**.

Большинство параметров (включение, издатель, название провайдера, области, управление доступом, разрешенные группы и пользователи, автоматическое создание пользователей, поведение HTTP Basic Auth и т. д.) управляются на этой странице и хранятся в базе данных.

Для аутентификации в REST API с помощью Bearer JWT укажите **JWT-аудитория API**, если ваш провайдер выпускает токены доступа для отдельной аудитории API. Если поле пустое, Poznote принимает в качестве аудитории JWT настроенный OIDC Client ID.

Следующие параметры остаются в файле `.env`:

```bash
POZNOTE_OIDC_CLIENT_ID=your_client_id
POZNOTE_OIDC_CLIENT_SECRET=your_client_secret
POZNOTE_OIDC_DISABLE_NORMAL_LOGIN=false
```

Используйте `POZNOTE_OIDC_DISABLE_NORMAL_LOGIN=true`, если хотите скрыть локальную форму с именем пользователя и паролем и разрешить вход только через SSO. Это единственный переключатель, который блокирует аутентификацию по паролю: он убирает форму, отклоняет POST-запросы с паролем на стороне сервера и скрывает настройку «Сменить пароль».

> **Восстановление доступа при сбое провайдера удостоверений.** Режим «только SSO» означает ровно это: пока `POZNOTE_OIDC_DISABLE_NORMAL_LOGIN=true`, никто не может войти по паролю, включая администраторов, поэтому запасного выхода в браузере нет. Так сделано намеренно: злоумышленник, завладевший учетной записью администратора, не сможет снова включить вход по паролю, чтобы обеспечить себе постоянный доступ. Для восстановления нужен доступ к серверу: задайте `POZNOTE_OIDC_DISABLE_NORMAL_LOGIN=false` в `.env`, перезапустите контейнер и войдите с локальным паролем. Перед включением режима «только SSO» убедитесь, что хотя бы у одной учетной записи администратора задан явный пароль (**Настройки > Инструменты администратора > Управление пользователями**), иначе возврат флага не поможет. Учтите, что у профиля администратора, автоматически созданного через OIDC, нет пароля, пока его не зададут.

> **Несовместимое изменение:** прежние настройки OIDC в `.env` больше не считываются, за исключением `POZNOTE_OIDC_CLIENT_ID`, `POZNOTE_OIDC_CLIENT_SECRET` и `POZNOTE_OIDC_DISABLE_NORMAL_LOGIN`. После обновления заново введите остальные настройки OIDC на странице администратора.

#### Пример управления доступом (группы + автоматическое создание)

На странице администрирования OIDC настройте:
- **Клейм групп:** `groups`
- **Разрешенные группы:** `poznote`
- **Автоматически создавать профили пользователей при первом входе через OIDC:** включено

Если автоматическое создание включено, Poznote формирует имя пользователя из клеймов OIDC (`preferred_username`, `nickname`, локальная часть email, `name`, затем `sub`) и сохраняет OIDC subject в созданном профиле.

</details>

<a id="app-passwords"></a>
<details>
<summary><strong>Пароли приложений (для приложений, расширений и скриптов)</strong></summary>
<br>

Приложения не могут входить через провайдера удостоверений так, как это делает браузер. **Пароль приложения** представляет собой отдельные учетные данные, которые вы создаете для одного клиента и можете отозвать в любой момент, так что вам никогда не придется сообщать пароль своей учетной записи.

Создайте его в **Настройки > Пароли приложений**: укажите название (клиент, который будет его использовать), при желании срок действия, и скопируйте сгенерированный секрет. Он показывается один раз и больше никогда.

Затем в клиенте введите **ваше обычное имя пользователя** и **пароль приложения** там, где запрашивается пароль. Больше ничего не меняется: он передается как обычный HTTP Basic Auth, поэтому все существующие клиенты работают без изменений.

```bash
curl -u 'username:pzn_2f7c…' https://YOUR_SERVER/api/v1/notes
```

#### Что пароль приложения может и чего не может

|  | |
|---|---|
| ✅ Читать и изменять заметки, папки, теги и вложения **своего профиля** | ❌ Открыть веб-интерфейс: форма входа его отклоняет |
| ✅ Работать, когда экземпляр в режиме «только SSO», в том числе при включенной опции *Отключить HTTP Basic Auth для API* | ❌ Обращаться к любой конечной точке `/api/v1/admin/*`, даже если учетная запись принадлежит администратору |
| ✅ Иметь срок действия и быть отозванным в любой момент | ❌ Сменить ваш пароль, изменить или удалить вашу учетную запись, создать другие пароли приложений |
| ✅ Обходиться без заголовка `X-User-ID`: он привязан к профилю, который его создал | ❌ Действовать от имени другого профиля, даже у администратора |

Благодаря этим ограничениям утечка пароля приложения раскрывает заметки только одной учетной записи, и ничего больше, а закрыть брешь можно, отозвав соответствующую строку.

Список в **Настройки > Пароли приложений** показывает для каждого пароля первые символы секрета (чтобы их различать), дату создания и дату последнего использования, поэтому неиспользуемые учетные данные легко заметить и удалить. Каждая учетная запись может иметь до 25 паролей.

> **На экземпляре в режиме «только SSO»** пароль приложения остается единственными учетными данными, которые API принимает через Basic Auth. У учетных записей, автоматически созданных через OIDC, пароля нет вообще, поэтому именно так их владельцы подключают расширение браузера, телефон или скрипт.

Полный справочник, включая конечные точки для управления ими: [документация REST API](docs/API-REST.md#authentication).

</details>

## Типы заметок

Poznote поддерживает два основных формата заметок, каждый из которых рассчитан на свой сценарий работы.

<details>
<summary><strong>HTML-заметки</strong></summary>
&nbsp;

*   **Редактор:** прямое визуальное редактирование WYSIWYG (What You See Is What You Get).
*   **Хранение:** сохраняются как файлы `.html` в каталоге данных пользователя. Поскольку это стандартный HTML, их можно открыть прямо в любом веб-браузере.
*   **Уникальные возможности:**
    *   **Богатое форматирование:** встроенная поддержка цвета текста, выделения и стандартных элементов HTML.
    *   **Интерактивный интерфейс:** непосредственная работа с элементами в редакторе.
</details>

<details>
<summary><strong>Markdown-заметки</strong></summary>
&nbsp;

*   **Редактор:** редактор синтаксиса Markdown с предпросмотром в реальном времени.
*   **Хранение:** сохраняются как файлы `.md` в каталоге данных пользователя.
*   **Уникальные возможности:**
    *   **Диаграммы Mermaid:** встроенная поддержка построения диаграмм (блок-схемы, диаграммы последовательности и т. д.) с помощью блоков кода ` ```mermaid `.
    *   **Математические формулы:** полноценная поддержка LaTeX для математических формул с синтаксисом `$ inline $` и `$$ block $$`.
    *   **Переносимость:** стандартный формат Markdown, совместимый с любым внешним редактором или генератором статических сайтов.
</details>

<details>
<summary><strong>Списки задач</strong></summary>
&nbsp;

*   **Назначение:** управление задачами и проектами с помощью интерактивных чек-листов.
*   **Работа:** отслеживайте прогресс с помощью флажков, которые можно переключать прямо в редакторе или в списке заметок. Индикатор прогресса показывает степень выполнения каждого списка.
*   **Параметры задачи:** у каждой задачи может быть срок выполнения с необязательным временем, напоминание, срабатывающее в назначенное время, и отметка важности; задачу также можно переместить в другой список.
*   **Страница «Задачи»:** отдельная страница **Задачи**, открываемая с левой панели значков, собирает в одном месте все задачи из ваших списков задач и, по желанию, флажки из обычных заметок. На ней есть фильтры по статусу (к выполнению, важные, просроченные, с датой, выполненные), текстовый фильтр и календарь задач, у которых указан срок.
*   **Публичная совместная работа:** списками задач можно делиться по публичной ссылке. Если выданы права на редактирование, внешние участники могут отмечать пункты списка без учетной записи Poznote.
</details>

<details>
<summary><strong>Ярлыки</strong></summary>
&nbsp;

*   **Функция:** создание ссылки на существующую заметку в другом месте.
*   **Пример использования:** позволяет обращаться к одной заметке сразу из двух разных мест. Например, заметка может лежать в папке для классификации, а ее ярлык отображаться на доске Канбан для текущего отслеживания.
</details>

<details>
<summary><strong>Шаблоны</strong></summary>
&nbsp;

*   **Функция:** повторное использование заранее подготовленного содержимого для единообразия документации, от целой заметки до короткого фрагмента.
*   **Настройка:** поместите заметки, которые хотите использовать повторно, в папку с именем `Templates` (вложенные папки допускаются). Рабочее пространство с именем `Templates` тоже подходит, и его шаблоны предлагаются из любого рабочего пространства. Имя также распознается на языке интерфейса (`Modèles`, `Vorlagen`, `Plantillas`, `Modelos`, `Шаблоны`, `模板`).
*   **Вставка в заметку:** введите `/template` (или `/` и название шаблона) в HTML- или Markdown-заметке и выберите шаблон: его содержимое вставляется в позицию курсора и преобразуется, если шаблон и заметка разных типов.
*   **Новая заметка из шаблона:** дублируйте заметку-шаблон или целую папку `Templates`, чтобы начать проект с готовой структурой папок.
</details>

<details>
<summary><strong>Ежедневные заметки (Дневник)</strong></summary>
&nbsp;

*   **Назначение:** ведите по одной заметке в день, в стиле журнала, с отдельной доски **Дневник**.
*   **Работа:** кнопка «Создать запись за сегодня» создает сегодняшнюю заметку (когда заметка уже есть, кнопка называется «Перейти к записи за сегодня»); заметка получает в качестве заголовка текущую дату и автоматически сохраняется в структуре папок `Diary/YYYY/MM`.
*   **Доска:** записи отображаются карточками, сгруппированными по месяцам (сначала новые), а фильтр помогает быстро найти прошлые записи.
*   **Лента записей:** кнопка со свитком рядом с настройками вида переключает на одну колонку для чтения: каждая запись целиком, сначала новые, с подгрузкой по мере прокрутки. Фильтр работает и здесь.
*   **Формат:** новые записи создаются как HTML- или Markdown-заметки в зависимости от настройки «Формат записей дневника» в **Настройки > Поведение**.
</details>

## Снимки

Снимки хранят предыдущие версии содержимого заметки, чтобы вы могли вернуться к прежнему состоянию через меню **Снимки** заметки.

*   **Автоматические:** снимок создается при первом открытии заметки за день. Для каждой заметки хранятся 3 последних автоматических снимка; это число можно изменить в **Настройки > Поведение > Снимки**.
*   **Ручные:** «Сделать снимок сейчас» добавляет снимок в любой момент, как и сочетание **Ctrl + Alt + S** (Cmd + Alt + S на Mac) при открытой заметке. Количество ручных снимков не ограничено, и они не учитываются в этом числе.
*   **Перед правкой ИИ:** снимок создается автоматически непосредственно перед тем, как [ИИ-ассистент](#ии-ассистент) или [MCP-сервер](#mcp-сервер) изменит содержимое заметки, так что неудачную переработку можно отменить одним щелчком. В истории такие снимки помечены «До правки ИИ» или «До правки MCP», они не создаются, если последний снимок уже содержит то же самое, и для каждой заметки хранятся 20 последних из них; это число можно изменить в **Настройки → Снимки** (от 1 до 200), если на вашем экземпляре многие заметки редактируются через ИИ или MCP.
*   **Срок хранения:** каждый снимок, автоматический или ручной, удаляется через 30 дней после создания. Снимок также можно удалить вручную в окне «Снимки».
*   **Вложения и изображения:** снимки хранят только текст заметки. Вложения никогда не копируются, поэтому файл, на который ссылаются несколько снимков, существует на диске в одном экземпляре. Файл, удаленный из заметки, остается на диске (скрытым от заметки), пока он есть хотя бы в одном снимке, поэтому восстановление такого снимка возвращает его. Файл удаляется окончательно, когда истекает срок хранения последнего содержащего его снимка или этот снимок удаляют, а также когда заметка удаляется безвозвратно. Поэтому хранение большего числа снимков никогда не дублирует файлы. Оно лишь дольше сохраняет удаленные файлы, не более 30 дней.

## Персонализация

Poznote предлагает несколько встроенных вариантов персонализации прямо в приложении, без необходимости менять конфигурационные файлы.

<details>
<summary><strong>Настройки отображения, поведения и Markdown</strong></summary>
<br>

В **Настройки > Отображение** можно настроить:

- **Шрифт приложения:** выбор гарнитуры, используемой во всем интерфейсе
- **Размер шрифта:** размер текста для заметок, боковой панели, блоков кода и страницы настроек
- **Цвета заметок:** палитра, предлагаемая при окрашивании заметки
- **Значки по типу заметки:** собственные значки для списков задач и Markdown-заметок в списке заметок
- **Масштаб иконок в списке:** размер значков в указателе заметок
- **Порядок боковой панели значков:** порядок кнопок на левой панели значков
- **Ширина содержимого заметки:** максимальная ширина области редактора заметок
- **Предпросмотр вложений:** отображение вложений в виде превью внутри заметки
- **Рамка изображения по умолчанию:** рамка вокруг вставленных изображений без добавления отступов
- **Выделять текущее дерево папок:** затемнение заметок и папок за пределами иерархии папок, в которой вы работаете
- **Заголовок страницы входа:** заголовок, отображаемый на странице входа
- **Видимость элементов:** скрытие неиспользуемых элементов интерфейса, см. ниже

В **Настройки > Поведение** можно настроить:

- **Сортировка заметок:** порядок заметок в списке
- **Фильтр по дате:** показ только заметок, обновленных за выбранное число дней
- **Снимки:** сколько автоматических снимков хранится для каждой заметки
- **Позиция новых задач:** место, куда вставляются новые задачи
- **Показывать заметки после папок:** вывод заметок без папки под списком папок
- **Перенос строк в блоке кода:** включение или отключение переноса строк в блоках кода
- **Формат записей дневника:** создание записей дневника как HTML- или Markdown-заметок
- Язык интерфейса, часовой пояс и формат даты, вложения и обратные ссылки внизу заметки, проверку орфографии и сочетания клавиш

В **Настройки > Markdown** можно настроить режим просмотра по умолчанию, шрифт редактора, Markdown в рамке и цветной Markdown, а также нумерацию строк в блоках кода.

Тема здесь не представлена карточкой: кнопка внизу левой панели значков переключает темы по кругу, а администратор выбирает, какие из них она предлагает, в **Настройки > Инструменты администратора > Список тем**.

Примечания:

- Нажмите **Загрузить CSS-файл**, чтобы выбрать файл `.css` на своем компьютере.
- Каждый загруженный файл сохраняется, поэтому можно хранить несколько тем и переключаться между ними без повторной загрузки.
- В окне перечислены сохраненные файлы: выберите тот, который нужно применить ко всем пользователям, или **Без пользовательского CSS**, чтобы вернуться к встроенному оформлению, затем нажмите **Сохранить**.
- Загрузка файла с именем уже сохраненного файла заменяет эту тему.
- Файлы хранятся в `data/css/` (ваш том Docker), поэтому они сохраняются при обновлении образа.
- Нажмите значок корзины рядом с темой, чтобы удалить этот файл из тома.
- Poznote автоматически добавляет параметр `v=` для сброса кеша.
- Таблица стилей подключается ближе к концу `<head>`, поэтому она может переопределять стили приложения по умолчанию.
- Загружать, применять и удалять пользовательский CSS-файл могут только администраторы.

### Список тем

**Настройки > Инструменты администратора > Список тем** определяет, какие темы перебирает кнопка темы внизу панели значков: одна тема на каждое нажатие, в указанном порядке.

- Отметьте встроенные темы, которые хотите оставить, и не отмечайте те, которыми никто не пользуется.
- Отметьте сохраненный CSS-файл, чтобы предложить его как отдельную тему. Он получит значок палитры и имя файла.
- С помощью стрелок задайте порядок, в котором кнопка перебирает темы.
- Пользовательская тема накладывается на светлую или темную основу, а сам файл не может этого указать: выберите основу рядом с файлом. Именно это значение получает `data-theme`, поэтому таблице стилей, написанной для темного режима, здесь нужно значение **Тёмная**.
- Список является глобальной настройкой, поэтому все перебирают одни и те же темы; какая из них применяется, каждый пользователь выбирает сам.
- Пользователь, у которого выбрана тема, убранная из списка, сразу получает первую тему списка.
- Выбор пользовательской темы загружает этот файл только для данного пользователя, вместо таблицы стилей, примененной ко всему экземпляру.
- Удаление CSS-файла удаляет его и из списка.
- Если в списке только одна тема, переключать нечего, поэтому для администратора кнопка открывает этот список, а для остальных ничего не делает.

**Прежде чем писать CSS**, проверьте, не делает ли уже нужное вам одна из встроенных тем: кнопка темы внизу панели значков перебирает темы Светлая, Тёмная, Чёрная, Лавандовая, Сепия и Терминал.

### Примеры

Цвета, отступы, радиусы скругления и насыщенность шрифта заданы дизайн-токенами, поэтому большинство изменений сводится к короткому списку переопределений переменных, а не к борьбе с селекторами. Полный список находится в `src/public/css/tokens.css`.

**Изменение акцентного цвета**

```css
:root {
    --pz-accent: #d6336c;
    --pz-accent-hover: #a61e4d;
    --pz-accent-rgb: 214, 51, 108;   /* same colour, channels only, used for tints */
}
html[data-theme='dark'] {
    --dm-accent: #f783ac;            /* lighter, because it sits on a dark ground */
}
```

Токенов два, а не один, потому что *заливка* и *подпись* не могут быть одного цвета: `--pz-accent` заливает кнопки, а `--dm-accent` задает акцентный цвет текста в темном режиме.

**Перекраска значков панели инструментов заметки**

```css
.note-edit-toolbar .toolbar-btn i,
.note-edit-toolbar .toolbar-btn [class*="lucide-"],
.note-edit-toolbar .toolbar-btn:hover i,
.note-edit-toolbar .toolbar-btn:hover [class*="lucide-"] {
    color: #e5322d !important;
}
```

Значки представляют собой CSS-маски, закрашенные через `background-color: currentColor`, поэтому достаточно `color`. `!important` здесь нужен потому, что у некоторых из этих значков уже есть собственный цвет (звезда, когда заметка в избранном, значок публикации, когда заметка опубликована, скрепка, когда у заметки есть вложения).

**Более теплый интерфейс**

```css
:root {
    --pz-bg: #f6ecd8;          /* page and note background */
    --pz-surface: #efe0c4;     /* panels, cards, menus */
    --pz-text: #3b2c1a;
    --pz-border: #d4bd94;
}
```

**Создание полноценной темы**

Переопределите токены в `:root` для светлой темы и в `:root[data-theme='dark']` для темной, и больше ничего. `src/public/css/README.md` описывает каждый токен и содержит полный пример; встроенные темы Лавандовая, Сепия и Терминал в `src/public/css/tokens.css` устроены точно так же и написаны тем же способом.

Одно пока недоступно темам: несколько значков, цвет которых явно задан правилом страницы, в темном режиме отображаются стандартным серым цветом значков.

</details>

## Многопользовательский режим

> Не путайте с функцией [Несколько экземпляров](#несколько-экземпляров).

Poznote построен на многопользовательской архитектуре: у каждого профиля изолированное пространство данных, при этом возможна контролируемая совместная работа в одном экземпляре.

- **Изоляция данных**: у каждого профиля свои заметки, рабочие пространства, теги, папки, вложения и пользовательские настройки.
- **Аутентификация для каждого профиля**: пользователи входят со своим именем пользователя или адресом электронной почты и паролем. Пока пароль не изменен в интерфейсе, используются встроенные значения по умолчанию (`admin` для администраторов, `user` для обычных пользователей).
- **Управление пользователями**: администраторы могут создавать, отключать профили и управлять ими в **Настройки > Инструменты администратора > Управление пользователями**.
- **Делегированный доступ к учетной записи**: администраторы могут предоставить одному пользователю доступ к учетной записи другого. Если пользователь может открывать несколько учетных записей, Poznote после входа спрашивает, какую из них использовать, и явно показывает, когда сессия **действует от имени** другого пользователя.
- **Защита владельца и администратора**: открытие чужой учетной записи не передает права владения. Чувствительные действия, такие как смена пароля, резервное копирование и восстановление, настройка Git Sync и глобальные административные настройки, остаются доступны только соответствующему владельцу или администратору.
- **Общий доступ**: заметками, папками и целыми рабочими пространствами можно делиться с другими пользователями того же экземпляра или публично по специальным ссылкам. По умолчанию общий доступ только для чтения, но его можно сделать доступом с правом редактирования: редактирование текста для заметки, редактирование заметок для папки и три уровня для списка задач (только чтение, только отметка и снятие отметок, полное редактирование).
- **Блокировка одним редактором**: если у нескольких пользователей есть доступ к одной заметке, Poznote допускает только одного активного редактора одновременно. Остальные пользователи по-прежнему могут открыть заметку в режиме только для чтения, увидеть, кто сейчас удерживает блокировку, и перехватить редактирование, повторно открыв заметку после снятия или истечения блокировки.
- **Изоляция аккаунтов (режим SaaS)**: администраторы могут запретить обычным пользователям отдельные возможности, например просмотр других учетных записей экземпляра и предоставление им общего доступа или регистрацию личных вебхуков. На администраторов это никогда не распространяется. Для семейного или командного экземпляра оставьте все флажки снятыми.


### Архитектура и структура

Poznote использует главную базу данных (`data/master.db`) для общих координационных данных и отдельные базы данных и файлы для каждого пользователя с самим содержимым заметок.

```
data/
├── master.db                    # Profiles, global settings, shared links, account access, edit locks
├── css/                         # Custom CSS files uploaded by an administrator
└── users/
    ├── 1/                       # User ID 1 (default admin)
    │   ├── database/poznote.db  # User's notes database
    │   ├── entries/             # User's note files (HTML/MD)
    │   ├── attachments/         # User's attachments
    │   ├── snapshots/           # Earlier versions of the user's notes
    │   ├── backgrounds/         # Workspace background images
    │   └── backups/             # Backup archives prepared for download
    ├── 2/                       # User ID 2
    └── ...
```

## Журнал действий

Poznote хранит историю чувствительных операций, выполненных на экземпляре, чтобы администраторы могли видеть, что произошло, когда и кто это сделал. Журнал доступен в **Настройки > Инструменты администратора > Журнал действий** и открыт только администраторам.

Каждая запись содержит дату и время, затронутую учетную запись, действие и краткое описание, например название удаленного рабочего пространства или число удаленных заметок. Наведите указатель на значок справки в верхней части страницы, чтобы увидеть полный список регистрируемых операций, который охватывает:

- **Сессии**: входы и выходы.
- **Учетные записи**: изменения профиля (имя пользователя, email, имя), изменения квот, активацию и деактивацию, выдачу или отзыв роли администратора, удаление учетной записи, а также выдачу или отзыв делегированного доступа к учетной записи.
- **Рабочие пространства**: создание, удаление, открытие и закрытие общего доступа.
- **Данные**: создание и восстановление резервных копий, очистку корзины и безвозвратное удаление заметок.
- **Пароли приложений**: создание и отзыв.

Рутинные действия намеренно не регистрируются: запись заметки или ее перемещение в корзину не попадают в журнал, как и вызовы API с аутентификацией в каждом запросе, иначе журнал превратился бы в дамп трафика.

Журнал фиксирует сам факт операции, а не затронутые ею данные. **Содержимое заметок в него никогда не записывается**, как и теги, папки или вложения. Запись об удалении идентифицирует заметку по ее заголовку и рабочему пространству, чтобы событие можно было узнать, и ничего больше.

> **Пароли никогда не записываются в журнал** ни в каком виде. Там, где пароль имеет значение, например для защищенного общего рабочего пространства, фиксируется только то, что он задан.

По умолчанию записи хранятся 90 дней. Срок хранения можно изменить на 30, 90 или 365 дней либо сделать неограниченным, а очистить журнал вручную можно на той же странице.

## Вебхуки

Poznote может уведомлять внешние сервисы о событиях на экземпляре, отправляя исходящие вебхуки (HTTP-запросы POST с полезной нагрузкой JSON) на зарегистрированные вами конечные точки. Это упрощает подключение Poznote к инструментам автоматизации, таким как n8n, Zapier или ваши собственные скрипты. Poznote только отправляет вебхуки: что с ними делает принимающая сторона (отправляет письмо, запускает рабочий процесс и т. д.), решаете вы.

Есть два уровня вебхуков:

- **Веб-хуки администратора** (**Настройки > Инструменты администратора > Веб-хуки администратора**, только для администраторов): события экземпляра, такие как `user.created`, `user.updated`, `user.activated`, `user.deactivated`, `user.deleted`, `settings.language_changed`, `signup.cap_reached`, `quota.notes_reached` и `quota.storage_reached`.
- **Пользовательские вебхуки** (**Настройки > Пользовательские вебхуки**): каждая учетная запись может зарегистрировать собственные конечные точки для событий, связанных с ее содержимым: `note.created`, `note.shared` и события напоминаний. Эти события доставляются только на конечные точки, зарегистрированные учетной записью, которая их породила, и никогда на конечные точки другого пользователя.

Доставка выполняется JSON-запросами POST, подписанными HMAC-SHA256, если у вебхука задан секрет (та же схема, что у вебхуков GitHub). Содержимое заметок никогда не отправляется, полезная нагрузка содержит только метаданные, а события напоминаний существуют в трех вариантах, чтобы вы сами выбрали, сколько данных покидает экземпляр.

Полный справочник, охватывающий все события, точные поля полезной нагрузки (`data.user`, `data.note` и т. д.), проверку подписи с примерами кода, гарантии доставки и настройку URL экземпляра для прямых ссылок на заметки, приведен в **[документации по вебхукам](docs/WEBHOOKS.ru.md)**.

## Синхронизация с Git

Poznote поддерживает автоматическую и ручную синхронизацию с **GitHub**, **GitLab** (gitlab.com или собственный экземпляр) или **Forgejo**. Каждый пользователь настраивает свой репозиторий независимо. Общего глобального репозитория нет.

Git Sync работает с REST API провайдера по HTTPS, поэтому аутентификация всегда выполняется по токену. SSH-ключи не используются.

<details>
<summary><strong>Как настроить Git Sync</strong></summary>
<br>

**Шаг 1: включите функцию (администратор, в Настройки > Инструменты администратора)**

Включите переключатель **Синхронизация Git** в разделе **Инструменты администратора** страницы настроек. Это включает Git Sync глобально и делает карточку и настройку **Синхронизация с Git** на уровне пользователя доступными в **Настройки**.

---

**Шаг 2: каждый пользователь настраивает свой репозиторий (Настройки > Синхронизация с Git)**

| Поле | Описание |
|---|---|
| Провайдер | `GitHub`, `GitLab` или `Forgejo` |
| Базовый URL API | GitHub: заполняется автоматически (только чтение). GitLab: `https://gitlab.com/api/v4` или URL вашего экземпляра, например `https://gitlab.example.com/api/v4`. Forgejo: URL вашего экземпляра, например `https://forgejo.example.com/api/v1` |
| Токен доступа | GitHub PAT (`ghp_...`), токен GitLab с областью `api` (`glpat-...`, персональный токен или токен доступа проекта) или токен Forgejo (Settings > Applications) |
| Репозиторий | Формат `owner/repo`. GitLab: полный путь проекта, включая подгруппы, например `group/subgroup/project` |
| Ветка | По умолчанию: `main` |
| Имя / email автора | Используются в метаданных коммитов |

> 🔒 Токены доступа хранятся в зашифрованном виде с использованием AES-256-GCM. Ключ шифрования генерируется автоматически и хранится в `data/.app_secret`.

---

**Автоматическая синхронизация**

Если пользователь включил ее, Poznote будет автоматически:
- выполнять **Pull** при входе
- выполнять **Push** при каждом создании, изменении или удалении заметки

Ручные push и pull также доступны с помощью кнопок **Отправить** и **Загрузить** на левой панели значков.

---

**Синхронизируемые рабочие пространства**

По умолчанию синхронизируются все рабочие пространства. В **Настройки > Синхронизация с Git** каждый пользователь может ограничить Git Sync выбранными рабочими пространствами:

- Отправляются и загружаются только заметки и вложения из выбранных рабочих пространств.
- Pull никогда не затрагивает заметки в других рабочих пространствах.
- Push удаляет из репозитория файлы, не относящиеся к выбранным рабочим пространствам, поэтому репозиторий всегда точно отражает синхронизируемый набор.
- Кнопки Отправить и Загрузить на боковой панели, автоматический push и предложение выполнить pull появляются только при просмотре синхронизируемого рабочего пространства.

</details>

## Хранение вложений в S3

По умолчанию вложения заметок хранятся на локальном диске. Вместо этого администраторы могут хранить их в S3-совместимом объектном хранилище (AWS S3, MinIO, Garage, Cloudflare R2, Backblaze B2 и т. д.). Настройка действует для всех пользователей экземпляра.

<details>
<summary><strong>Как настроить хранилище S3</strong></summary>
<br>

Настройка выполняется в **Настройки > Вложения S3** (только для администраторов).

- **Конфигурация**: URL конечной точки, регион, бакет, ключ доступа, секретный ключ и адресация в стиле path, со встроенной проверкой подключения.
- **Миграция**: перенос существующих файлов вложений между локальным диском и бакетом в обоих направлениях и для всех пользователей. Миграция выполняется пакетами, ее можно безопасно прервать и возобновить.
- **Конфиденциальность**: вложения хранятся в бакете в `attachments/{user id}/` и всегда отдаются через Poznote, поэтому бакет может оставаться приватным.
- **Квоты**: можно задать квоту хранилища S3 для каждого пользователя, а использование S3 отображается в административной статистике хранилища.
- **Резервные копии**: ZIP-экспорты по умолчанию включают вложения из S3 (они загружаются из бакета на лету), независимо от того, созданы ли они в окне резервного копирования, через REST API или автоматическими резервными копиями S3. Параметр в окне резервного копирования позволяет исключить их, чтобы архив был легче. Если во время создания архива бакет недоступен для чтения, экспорт завершается ошибкой, а не создает архив с недостающими файлами.

Восстановление резервной копии, в которой нет части файлов вложений, на которые она ссылается, отклоняется, пока включено хранилище S3, потому что полное восстановление заменяет содержимое бакета и недостающие файлы были бы потеряны. Восстановить такую резервную копию можно двумя способами:

- **Самый простой**: отключите переключатель «Хранить вложения в S3» (учетные данные сохраните), восстановите резервную копию, затем снова включите переключатель. Восстановление в локальном режиме никогда не затрагивает бакет, а вложения, которые по-прежнему хранятся там, продолжают отдаваться. Это также правильный путь на новом сервере при целом бакете, поскольку экспорт вложений из второго способа требует экземпляра, который еще знает о заметках.
- **Пересобрать полный архив**:
  1. Скачайте **Экспорт вложений** в окне резервного копирования: он содержит все вложения вашей учетной записи в папке `files/`.
  2. Распакуйте резервную копию, скопируйте файлы из `files/` в папку `attachments/` резервной копии и снова упакуйте ее в ZIP. Будьте внимательны при повторной упаковке: выделите содержимое резервной копии (`database/`, `entries/`, `attachments/` и т. д.) и сожмите это выделение, а не папку, в которой оно лежит. Папки должны находиться в корне ZIP-архива, иначе при восстановлении появится сообщение об отсутствии `database/poznote_backup.sql`.
  3. Восстановите пересобранный ZIP-архив обычным образом.

> Пока включено хранилище S3, Git Sync игнорирует вложения.

</details>

## Резервные копии S3

Администраторы могут отправлять полные архивы резервных копий (по одному ZIP-архиву на пользователя, идентичному загрузке полной резервной копии) в S3-совместимый бакет вручную или автоматически по расписанию. Эта конфигурация не зависит от конфигурации хранения вложений в S3, поэтому резервные копии можно направлять в другой бакет или к другому провайдеру.

<details>
<summary><strong>Как настроить резервные копии S3</strong></summary>
<br>

Настройка выполняется в **Настройки > Резервные копии S3** (только для администраторов).

- **Главный переключатель**: переключатель вверху страницы включает или отключает всю функцию. Когда он выключен, автоматическое резервное копирование останавливается, а разделы резервного копирования и восстановления S3 исчезают у всех пользователей (действия самообслуживания также отклоняются на стороне сервера).
- **Конфигурация**: URL конечной точки, регион, бакет, ключ доступа, секретный ключ и адресация в стиле path, со встроенной проверкой подключения.
- **Выбор пользователей**: флажки определяют, каких пользователей охватывает резервное копирование. По умолчанию отмечены все, и пока отмечены все, новые учетные записи включаются автоматически.
- **Ручное резервное копирование**: кнопка «Создать копию сейчас» загружает свежий архив для каждого выбранного пользователя, по одному пользователю за раз, с отображением прогресса по каждому. Она работает, как только подключение настроено, даже если автоматическое резервное копирование выключено.
- **Автоматическое резервное копирование**: если оно включено, фоновый процесс создает резервные копии выбранных пользователей с заданной периодичностью (ежедневно, еженедельно или ежемесячно). Первый запуск происходит в течение нескольких минут после включения, следующие через выбранный интервал.
- **Хранение**: для каждого пользователя хранятся только N последних архивов, более старые удаляются из бакета после каждого резервного копирования (0 сохраняет все).
- **Просмотр**: на странице перечислены архивы, находящиеся в бакете, с действиями скачивания и удаления.
- **Восстановление**: архивы хранятся в бакете в `backups/{user id}/` и восстанавливаются через стандартную страницу [Восстановление / Импорт](#восстановление--импорт).
- **Самообслуживание**: после настройки бакета каждый пользователь получает раздел «Резервные копии S3» на своей странице «Резервное копирование / Экспорт», чтобы загрузить свежий архив своей учетной записи, а также скачивать или удалять существующие архивы. Раздел «Восстановление из S3» на странице «Восстановление / Импорт» восстанавливает учетную запись прямо из одного из этих архивов.
- **Изоляция аккаунтов**: два параметра («Резервные копии S3 на странице резервного копирования» и «Восстановление из S3 на странице восстановления») отключают эти разделы самообслуживания для обычных пользователей. Они применяются на стороне сервера, поэтому заблокированные действия отклоняются даже при прямом вызове.

Когда вложения хранятся в S3 (хранение вложений в S3), они по умолчанию включаются в архивы и загружаются из бакета на лету. Параметр позволяет исключить их из резервных копий, чтобы архивы были легче, а копирование быстрее.

</details>

## Резервное копирование / Экспорт

В Poznote есть встроенные функции резервного копирования и экспорта, доступные через настройки.

<a id="complete-backup"></a>
<details>
<summary><strong>Полная резервная копия в ZIP-архив Poznote</strong></summary>
<br>

Один ZIP-архив, содержащий базу данных, все заметки и вложения всех рабочих пространств:

  - Содержит `index.html` в корне для офлайн-просмотра
  - Заметки упорядочены по рабочим пространствам и папкам
  - Вложения доступны по кликабельным ссылкам

Архив создается в фоновом рабочем процессе, а не во время запроса, который его запускает, поэтому большая учетная запись не упрется в тайм-аут браузера или обратного прокси. Страница отслеживает ход задания, а скачивание начинается само, как только файл готов. Можно уйти со страницы и вернуться, подготовка продолжится. Подготовленный архив остается доступным 24 часа, а кнопка позволяет сразу его удалить.

#### Резервные копии пользователя и полные резервные копии

Poznote предлагает гибкие варианты резервного копирования:

**Через веб-интерфейс (Настройки > Резервное копирование / Экспорт):**
- **Все пользователи** могут создавать резервную копию своего профиля и восстанавливать его
- **Администраторы** могут выбрать, какой профиль пользователя сохранить или восстановить
- Резервные копии содержат базу данных, заметки и вложения пользователя

**Через API или скрипт (только администраторы):**
- Автоматическое резервное копирование с помощью скрипта `backup-poznote.sh`
- Программный доступ через REST API v1
- Требуются учетные данные администратора

**Охват резервных копий:**

1. **Резервные копии пользователя**: создаются в настройках или через API. Содержат *только* данные конкретного пользователя (его базу данных, заметки и вложения).
2. **Полная резервная копия системы**: создается вручную путем копирования всего каталога `/data`. Это единственный способ сохранить главную конфигурацию и данные всех пользователей за один раз.

```bash
# Полная резервная копия системы из командной строки
tar -czvf poznote-full-backup.tar.gz data/
```

</details>

<a id="export-individual-notes"></a>
<details>
<summary><strong>Экспорт отдельных заметок</strong></summary>
<br>

Экспортируйте отдельные заметки с помощью кнопки **Экспорт** на панели инструментов заметки:

  - **HTML-заметки:** экспорт в HTML или в один HTML-файл со встроенными изображениями
  - **Markdown-заметки:** экспорт в Markdown, в HTML или в один HTML-файл со встроенными изображениями
  - **Списки задач:** те же варианты, а также экспорт списка в исходном JSON

</details>

<a id="automated-backups-with-bash-script"></a>
<details>
<summary><strong>Автоматическое резервное копирование скриптом Bash</strong></summary>
<br>

Для автоматического резервного копирования по расписанию через API можно использовать прилагаемый скрипт `backup-poznote.sh`.

**ВАЖНО:** создавать резервные копии через API могут только администраторы.
Используйте текущий пароль профиля администратора, под которым вы проходите аутентификацию. При новой установке это пароль администратора по умолчанию (`admin`), пока его не сменят в Poznote. После того как задан собственный пароль, для вызовов API требуется именно он.

**Расположение скрипта:** `backup-poznote.sh` в папке `tools` репозитория Poznote

**Использование администратором:**

Администраторы могут создавать резервную копию любого профиля пользователя, **знать ID пользователей не нужно**, достаточно имени пользователя:

```bash
# Резервная копия собственного профиля
bash backup-poznote.sh 'https://poznote.example.com' 'admin' 'admin_password' 'admin' '/backups' '30'

# Резервная копия профиля другого пользователя (Nina)
bash backup-poznote.sh 'https://poznote.example.com' 'admin' 'admin_password' 'Nina' '/backups' '30'
```

**Использование:**
```bash
bash backup-poznote.sh '<poznote_url>' '<admin_username>' '<admin_password>' '<target_username>' '<backup_directory>' '<retention_count>'
```

**Пример с crontab (администратор создает резервную копию Nina):**

```bash
# Добавьте в crontab для автоматического резервного копирования дважды в день
0 0,12 * * * bash /root/backup-poznote.sh 'https://poznote.example.com' 'admin' 'admin_password' 'Nina' '/root/backups' '30'
```

**Описание параметров:**
- `'https://poznote.example.com'`: URL вашего экземпляра Poznote
- `'admin'`: имя администратора для аутентификации (должен быть администратором)
- `'admin_password'`: текущий пароль администратора для профиля API (по умолчанию `admin`, пока его не сменят, затем собственный пароль)
- `'Nina'`: имя пользователя, чью резервную копию нужно создать
- `'/root/backups'`: родительский каталог для хранения резервных копий (создается папка `backups-poznote-<username>`)
- `'30'`: число хранимых резервных копий (более старые удаляются автоматически)

**Как работает резервное копирование:**

1. Скрипт проходит аутентификацию с учетными данными администратора
2. Автоматически определяет ID пользователя по имени пользователя
3. Создает резервную копию через API
4. Вызывает REST API v1 Poznote (`POST /api/v1/backups` с заголовком `X-User-ID`)
5. Скачивает ZIP-архив резервной копии локально в `backups-poznote-<username>/`
6. Автоматически управляет хранением (оставляет только указанное число последних резервных копий)

**Примечание:** резервные копии каждого пользователя хранятся в отдельных папках (`backups-poznote-Nina`, `backups-poznote-Tim` и т. д.)

</details>


## Восстановление / Импорт

Poznote предлагает гибкие варианты восстановления через веб-интерфейс (**Настройки > Восстановление / Импорт**) или программно через REST API для администраторов. Пользователи могут восстановить данные своего профиля из полной резервной копии в ZIP или импортировать отдельные файлы, а администраторы могут управлять восстановлением во всей системе.

<a id="complete-restore"></a>
<details>
<summary><strong>Полное восстановление из ZIP-архива резервной копии Poznote</strong></summary>
<br>

Загрузите ZIP-архив полной резервной копии, чтобы восстановить все:

  - Заменяет базу данных, восстанавливает все заметки и вложения
  - Работает сразу для всех рабочих пространств

Практического ограничения размера нет. Архив загружается частями (неудачная часть отправляется повторно, а не срывает всю загрузку), собирается на сервере, затем распаковывается и восстанавливается фоновым рабочим процессом, поэтому ни браузер, ни обратный прокси перед экземпляром не могут прервать восстановление по тайм-ауту. Индикатор прогресса охватывает весь процесс: загрузку, распаковку, базу данных, заметки и вложения. По завершении восстановления Poznote спрашивает, какое рабочее пространство открыть.

Восстановление из бакета S3 (см. [Резервные копии S3](#резервные-копии-s3)) выполняется тем же фоновым заданием, поэтому получение большого архива из бакета и его восстановление тоже не зависят от того, остается ли запрос активным.

Если загрузка невозможна вовсе, страница «Восстановление / Импорт» предлагает и запасной вариант с прямым копированием: скопируйте архив в контейнер Poznote точно по пути `/tmp/backup_restore.zip` по SSH, перезагрузите страницу и выполните восстановление оттуда.

</details>

<details>
<summary><strong>Импорт отдельных файлов</strong></summary>
<br>

Импортируйте напрямую одну или несколько заметок в формате HTML, Markdown или текста:

  - Поддерживаются типы файлов `.html`, `.md`, `.markdown`, `.txt` и `.json`
  - Одновременно можно выбрать до 50 файлов, это значение настраивается в Настройки > Инструменты администратора > Лимиты импорта

</details>

<a id="import-zip-notes"></a>
<details>
<summary><strong>Импорт ZIP-файла</strong></summary>
<br>

Импортируйте ZIP-архив с несколькими заметками:

  - Поддерживаются типы файлов `.html`, `.md`, `.markdown` или `.txt`
  - ZIP-архивы могут содержать до 300 файлов, это значение настраивается в Настройки > Инструменты администратора > Лимиты импорта
  - При импорте ZIP-архива Poznote автоматически определяет и воссоздает структуру папок

Практического ограничения размера архива нет. Как и при полном восстановлении, он загружается частями (неудачная часть отправляется повторно, а не срывает всю загрузку), собирается на сервере, затем обрабатывается фоновым рабочим процессом, поэтому ни браузер, ни обратный прокси перед экземпляром не могут прервать импорт по тайм-ауту. Индикатор прогресса охватывает весь процесс: загрузку, изображения и вложения, затем заметки.

<a id="import-obsidian-notes"></a>
<details>
<summary><strong>Импорт заметок Obsidian</strong></summary>
<br>

Импортируйте ZIP-архив с несколькими заметками из Obsidian:

  - ZIP-архивы могут содержать до 300 файлов, это значение настраивается в Настройки > Инструменты администратора > Лимиты импорта
  - Poznote автоматически определяет и воссоздает структуру папок
  - Poznote автоматически находит существующие теги и создает их
  - Poznote автоматически импортирует изображения, если они находятся в корне ZIP-архива

</details>

<details>
<summary><strong>Поддержка front matter в Markdown</strong></summary>
<br>

Файлы Markdown могут содержать front matter в формате YAML для задания метаданных заметки. Поддерживаются следующие ключи:

  - `title`: переопределяет заголовок заметки (по умолчанию: имя файла без расширения)
  - `folder`: переопределяет целевую папку. Простое имя должно совпадать с папкой, уже существующей в рабочем пространстве; путь вида `Projects/2026` создает недостающие папки.
  - `tags`: массив тегов, применяемых к заметке. Поддерживается как однострочный синтаксис `[tag1, tag2]`, так и многострочный
  - `favorite`: отмечает заметку как избранную (`true` или `false`)
  - `created`: задает собственную дату создания (формат: `YYYY-MM-DD HH:MM:SS`)
  - `updated`: задает собственную дату изменения (формат: `YYYY-MM-DD HH:MM:SS`)

Пример с однострочным синтаксисом массива:
```yaml
---
title: My Important Note
folder: Projects
tags: [important, work]
favorite: true
created: 2024-01-15 10:30:00
updated: 2024-01-20 15:45:00
---
```

Пример с многострочным синтаксисом:
```yaml
---
title: My Important Note
folder: Projects
tags:
  - important
  - work
favorite: true
created: 2024-01-15 10:30:00
updated: 2024-01-20 15:45:00
---
```

</details>


## Офлайн-просмотр

**📦 Полная резервная копия** создает автономную офлайн-версию ваших заметок. Просто распакуйте ZIP-архив и откройте `index.html` в любом веб-браузере. Так вы сможете читать заметки без подключения к сети, но без полной функциональности Poznote: это экспорт только для чтения.

## Несколько экземпляров

> Не путайте с функцией [Многопользовательский режим](#многопользовательский-режим).

На одном сервере можно запустить несколько изолированных экземпляров Poznote. У каждого экземпляра свои данные, порт и учетные данные.

Идеально подходит для:
- Размещения для разных пользователей на одном сервере, у каждого из которых свой отдельный экземпляр и учетная запись
- Тестирования новых функций без влияния на рабочий экземпляр

Просто повторите шаги установки в разных каталогах с разными портами.

### Пример: экземпляры Tom и Alice на одном сервере

```
Server: my-server.com
├── Poznote-Tom
│   ├── Port: 8040
│   ├── URL: http://my-server.com:8040
│   ├── Container: poznote-tom-webserver-1
│   └── Data: ./poznote-tom/data/
│
└── Poznote-Alice
  ├── Port: YOUR_POZNOTE_API_PORT
  ├── URL: http://my-server.com:YOUR_POZNOTE_API_PORT
    ├── Container: poznote-alice-webserver-1
    └── Data: ./poznote-alice/data/
```

## ИИ-ассистент

В Poznote встроен ИИ-чат, который подключается к любому OpenAI-совместимому серверу, к локальному экземпляру [Ollama](https://ollama.com) или [LM Studio](https://lmstudio.ai) либо к облачному провайдеру, например [Anthropic (Claude)](https://www.anthropic.com) или OpenAI. После настройки на левой панели значков, на странице заметок и на панели управления появляется кнопка **ИИ-ассистент**, которая открывает панель чата прямо там.

Ассистент глобальный, в стиле MCP: у него есть инструменты для **поиска и чтения ваших заметок**, и он сам использует их, чтобы отвечать на вопросы вроде «что говорится в моих заметках о X?», составлять сводки по нескольким заметкам или находить заметку, которую вы помните лишь смутно. Если вы явно попросите, он также может **создавать, переименовывать и переписывать заметки**, **упорядочивать их** (теги, папки, избранное, напоминания, задачи и флажки) и **перемещать заметки и папки в корзину** (но никогда не удаляет их безвозвратно). Ответы передаются потоком и отображаются в формате Markdown.

Ассистент **ограничен текущим рабочим пространством**: он видит, ищет и редактирует только заметки рабочего пространства, в котором вы открыли чат, и новые заметки создаются там же. Чтобы спросить о другом рабочем пространстве, сначала переключитесь на него.

Чтобы включить его, откройте **Настройки → Инструменты администратора → ИИ-ассистент** (только для администратора), выберите провайдера и нажмите **Проверить доступ и получить список моделей**, чтобы проверить сервер и выбрать одну из предлагаемых им моделей. Конфигурация действует на весь экземпляр: как только администратор включит чат, он появляется у каждого профиля пользователя.

Администратор также может разрешить личные API-ключи. Тогда каждый пользователь получает в своих настройках карточку **Мой ИИ-ассистент**, чтобы направить чат на собственный сервер, провайдера и ключ вместо общих для экземпляра.

Полное руководство по настройке, охватывающее провайдеров, выбор модели и подключение локального сервера Ollama/LM Studio из контейнера Poznote (поиск правильного URL, `OLLAMA_HOST`, сеть Docker), приведено в [документации ИИ-ассистента](docs/AI-ASSISTANT.ru.md).

Сервер ИИ вызывается с сервера Poznote, а не из вашего браузера. С локальным экземпляром Ollama ваши заметки и переписка никогда не покидают ваш компьютер. Чтобы вместо этого доверить управление заметками внешнему ИИ-ассистенту (VS Code Copilot, Claude CLI...), см. раздел [MCP-сервер](#mcp-сервер) ниже.

## Транскрибация (преобразование речи в текст)

Превращайте голос в текст заметки с помощью собственного сервера распознавания речи. Poznote не содержит встроенной речевой модели: он работает с любым сервером, предоставляющим аудио-API OpenAI (`POST /v1/audio/transcriptions`), например с самостоятельно размещенным Whisper, поэтому звук никогда не покидает ваш компьютер.

Как только администратор включит эту функцию в **Настройки → Инструменты администратора → Транскрибация**, в меню слэш-команд в разделе **Вставка** появится пункт **Диктовка**, а у аудиовложений появится кнопка **Транскрибировать**.

Настройка сервера, выбор модели и все остальное описаны в [документации по транскрипции](docs/TRANSCRIPTION.ru.md).

## MCP-сервер

В Poznote есть сервер Model Context Protocol (MCP), который позволяет ИИ-ассистентам, таким как GitHub Copilot, работать с вашими заметками на естественном языке. Например:

- «Создай новую заметку с заголовком 'Meeting Notes' и содержимым...»
- «Найди заметки про 'Docker'»
- «Покажи все заметки в моем рабочем пространстве Poznote»
- «Обнови заметку 42, добавив новую информацию»

<p align="center">
  <img src="docs/mcp-poznote.gif" alt="Poznote MCP Server demo" width="100%">
</p>

Инструкции по настройке и использованию приведены в [документации MCP-сервера](docs/MCP-SERVER.ru.md).

MCP-сервер использует настройки по умолчанию (порт `8045`, отладка выключена). Чтобы их переопределить:

```bash
POZNOTE_MCP_PORT=9000 POZNOTE_DEBUG=true docker compose up -d --force-recreate mcp-server
```

Это переопределения контейнера и среды выполнения, а не настройки интерфейса Poznote. Их можно передать прямо в команде, как показано выше, или указать в `.env` перед пересозданием контейнера `mcp-server`.

MCP-сервер распознает для `POZNOTE_DEBUG` только точные значения в нижнем регистре `true` и `false`, а для всего остального использует `false` (веб-сервер менее строг и также принимает `1`, `on` или `yes`). После изменения настроек пересоздайте контейнер; простой перезапуск не перечитывает переменные окружения.

**Безопасность:** порт MCP публикуется только на `127.0.0.1`, поэтому по умолчанию к нему нельзя подключиться извне вашего компьютера. Если вы открываете его шире (обратный прокси, локальная сеть или установка без Docker), задайте `POZNOTE_MCP_AUTH_TOKEN` в `.env`, и сервер будет требовать заголовок `Authorization: Bearer <token>` от каждого клиента. При запуске вне Docker `poznote-mcp serve` по умолчанию привязывается к `127.0.0.1`. Подробности в [разделе о безопасности](docs/MCP-SERVER.ru.md#безопасность) документации MCP.

## Расширение для Chrome

**Poznote URL Saver** представляет собой расширение браузера, которое позволяет одним щелчком быстро сохранить URL или даже скриншот всей текущей страницы в ваш экземпляр Poznote.

<p align="center">
  <img src="images/chrome-extension.png" alt="Poznote Chrome Extension" width="50%">
</p>

Установите расширение прямо из Chrome Web Store → [Установить расширение](https://chromewebstore.google.com/detail/bmjclfamahegmgillaghhmnbkjebipbh?utm_source=item-share-cb)

#### Подключение к вашему экземпляру

1. В Poznote откройте **Настройки > Пароли приложений**, создайте пароль с названием расширения и скопируйте показанный секрет. Он отображается один раз.
2. Откройте расширение и заполните поля:
   - **App URL:** адрес вашего экземпляра, например `https://notes.example.com/`
   - **Username:** ваше имя пользователя Poznote
   - **Password:** только что скопированный пароль приложения
   - **Workspace** и, при желании, **Folder**: куда должны попадать сохраненные страницы
3. Сохраните. Расширение само определит ваш профиль и будет готово к работе.

Пароль учетной записи здесь тоже подходит, но для расширения лучше использовать пароль приложения: он дает доступ только к API, но никогда к веб-интерфейсу или настройкам вашей учетной записи, ограничен вашим собственным профилем, а его отзыв в Poznote отключает расширение, ничего больше не меняя. Полный список ограничений приведен в разделе [Пароли приложений](#app-passwords).

> **Если ваш экземпляр работает в режиме «только SSO»,** пароль приложения остается единственным способом подключить расширение: формы входа, которая нужна расширению, для вашей учетной записи не существует. Создайте его в **Настройки > Пароли приложений** точно так же, как описано выше.

## Отправка в Poznote на Android

На Android после установки PWA Poznote появляется в системном меню **Поделиться**. Поделитесь страницей из Chrome (или ссылкой либо текстом из любого приложения), выберите Poznote, и будет создана новая заметка с заголовком страницы и кликабельной ссылкой, без всякого расширения.

Как это использовать:

1. Откройте свой экземпляр Poznote в Chrome на Android и установите его как приложение (меню → **Добавить на главный экран** → **Установить**).
2. В любом приложении нажмите **Поделиться** и выберите **Poznote**.

> Если Poznote не сразу появляется в меню «Поделиться», убедитесь, что приложение установлено (а не просто добавлено в закладки). Если вы установили PWA до выхода этой функции, Chrome автоматически подхватит новую возможность через несколько дней или сразу, если переустановить приложение.

## Документация API

Poznote предоставляет полноценный RESTful API v1 для программного доступа к заметкам, папкам, рабочим пространствам, тегам, вложениям, резервным копиям, настройкам и многому другому.

Полный справочник API со всеми конечными точками, параметрами и примерами curl приведен в **[документации REST API](docs/API-REST.md)**.

### Быстрый старт

```bash
# Список всех заметок пользователя с ID 1
curl -u 'username:password' -H "X-User-ID: 1" \
  http://YOUR_SERVER/api/v1/notes

# То же самое с паролем приложения, созданным в Настройки > Пароли приложений
# (работает на экземплярах в режиме «только SSO»; X-User-ID подразумевается)
curl -u 'username:pzn_2f7c…' http://YOUR_SERVER/api/v1/notes

# Создание заметки
curl -X POST -u 'username:password' -H "X-User-ID: 1" \
  -H "Content-Type: application/json" \
  -d '{"heading": "My Note", "content": "Hello!", "type": "markdown"}' \
  http://YOUR_SERVER/api/v1/notes
```

### Интерактивная документация (Swagger)

Откройте **Swagger UI** прямо в Poznote через `Settings > About > API REST`, чтобы просмотреть все конечные точки и схемы запросов и ответов, а также интерактивно протестировать вызовы API.

## Технологический стек

Poznote ставит во главу угла простоту и переносимость: никаких сложных фреймворков и тяжелых зависимостей. Только понятные и надежные веб-технологии, благодаря которым ваши заметки остаются доступными и под вашим контролем.

**Архитектура с приоритетом конфиденциальности:** Poznote работает полностью локально, и для его функционирования не требуются внешние подключения. Все библиотеки (Excalidraw, Mermaid, KaTeX) входят в комплект и отдаются вашим собственным экземпляром. Сразу после установки единственное исходящее подключение представляет собой ежедневную проверку обновлений; другие возможны только у необязательных функций, которые вы включаете сами (Git Sync, S3, провайдер ИИ, вебхуки, SMTP, OIDC).

- **AJAX**: асинхронная загрузка данных

- **CodeMirror 6**: расширяемый редактор кода и текста для редактирования Markdown

- **Mermaid**: клиентская библиотека JavaScript для построения диаграмм и блок-схем из текста

- **Файлы HTML/Markdown**: заметки хранятся в файловой системе как обычные файлы HTML или Markdown
- **База данных SQLite**: метаданные, теги, связи и данные пользователей
- **Вложения**: хранятся в локальной файловой системе или, по желанию, в S3-совместимом объектном хранилище

### Инфраструктура
- **Nginx + PHP-FPM**: высокопроизводительный веб-сервер с FastCGI Process Manager
- **Alpine Linux**: безопасный и легковесный базовый образ
- **Docker**: контейнеризация для простого развертывания и переносимости
- **Python 3.12 (Alpine)**: среда выполнения MCP-сервера с библиотеками httpx, uvicorn и fastmcp для интеграции с ИИ-ассистентами
